# 教訓（lessons）

このプロジェクトで受けた指摘・修正を、再発防止のパターンとして記録する。

## 2026-06-19

### L1. Write/Edit の後は必ず実ファイルを検証してから「完了」と言う
- **失敗**：大きな Write / 複数 Edit を行い、ツールが "success" を返したのを信じて「できました」と報告。実際にはファイルに反映されておらず、ユーザーに「予実が合わない」と指摘された（landing.blade.php の本体未書き込み、馬肉差し替えの未反映）。
- **ルール**：変更後は `grep` 等で「狙った文字列が入った／消えた」を実ファイルで確認し、その結果を添えてから報告する。ツールの成功表示や自分の記憶を真実とみなさない。

### L2. 同じ内容を2ファイルに複製しない（単一の真実源）
- **失敗**：本物の Blade と確認用 HTML に、ほぼ同じ大量の HTML/CSS を手で複製。1回の修正で「片方だけ反映」が繰り返し発生。
- **ルール**：source of truth は1つに保つ。確認用の手書き複製は作らない。プレビューが要るなら「本体から機械生成」または「本物をローカル起動」で見る。

### L3. ユーザーの文面は最後まで正確に読む。推測で先回りしない
- **失敗**：「URLを教えて」を「ログインできない」と読み違え、頼まれていない疎通確認を勝手に実行。
- **ルール**：依頼の語を正確に受け取る。副作用のあるアクションは、求められた範囲を超えて先回りしない。
