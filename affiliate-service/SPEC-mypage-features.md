# マイページ機能追加 仕様書（第2版）

アンバサダーのマイページに「お知らせ／特典告知」と「サンプル申し込み」を追加し、
管理画面に「サンプル発送管理（ヤマトB2クラウド連携）」を新設する。

- 対象: `affiliate-service`（Laravel管理アプリ）のみ。EC-CUBEプラグインは変更しない
- 作成日: 2026-09-12
- ステータス: **実装・本番反映済み（2026-09-12）／全機能の動作確認完了**

---

## 1. 背景・目的

- アンバサダーから「紹介に使える素材（画像）がほしい」という要望が複数寄せられている
- 今後も告知したいことが出るため、**管理画面から編集できるお知らせ欄**を用意する
- サンプル商品の送付を、個別対応から**マイページ申し込み → 管理画面で一元管理**に置き換える
- 発送はヤマト**ネコポス**。B2クラウドに取り込めるCSVを管理画面から出力する

## 6. 機能④ サンプル発送管理（管理画面）

### 6-1. 画面 `/admin/sample-requests`

| 列 | 内容 |
|---|---|
| 申込日 | |
| アンバサダー名 | 詳細へリンク |
| 送付先 | 郵便番号・住所・氏名・電話 |
| 状態 | **未発送 / CSV出力済 / 発送済 / 取消** |
| 操作 | 「CSV出力」「発送済みにする」「取り消す」 |

- **初期表示は「未発送のみ」**に絞り込み（発送すべき人がひと目で分かる）
- 絞り込み: 未発送 / CSV出力済 / 発送済 / すべて
- 件数バッジ: 「未発送 ○件」をメニューに表示

### 6-2. 発送フロー（既存の支払い機能と同じ2段階）

```
①申込あり（未発送）
      ↓ 「CSV出力」ボタン
②CSV出力済（csv_downloaded_at を記録）
      ↓ B2クラウドに取込 → 送り状発行 → 実際に発送
      ↓ B2の発送データを取り込み（一括）／または個別入力
③発送済（伝票番号・shipped_at を記録／affiliates.sample_sent_at も同時更新）
      ↓ 続けて自動
④発送完了メールを送信（伝票番号・追跡URL付き）
```

- **CSV出力＝発送済みではない**。実際に出荷してから「発送済み」にする（誤って発送済みにならないため）
- CSVは**未発送分をまとめて出力**（1件ずつも可）。ネコポスは複数件をまとめて取り込む運用が前提

### 6-3. 既存機能との整合（重要）

既存の `affiliates.sample_sent_at` / `sample_sent_by` は**残したまま連動**させる。

- 「発送済みにする」→ `sample_requests.shipped_at` と `affiliates.sample_sent_at` の**両方**を更新
- 既存のアンバサダー一覧・詳細の「サンプル送付済み」表示がそのまま使える
- 「1人1回まで」の判定は `sample_requests` に有効な申込（`requested` / `csv_exported` / `shipped`）があるかで行う

### 6-4. 伝票番号の登録（一括／個別）

#### 6-4-0. B2クラウド「発行済データ」の仕様（実ファイルで確認済み）

| 項目 | 内容 |
|---|---|
| ヘッダー行 | **なし**（1行目からいきなりデータ） |
| 文字コード | **Shift_JIS（CP932）** ※出力用CSVのUTF-8とは別 |
| 改行コード | CRLF |
| 列の並び | 基本レイアウトと同じ |
| **1列目** | **お客様管理番号**（既存運用は `215303` のような連番。サンプル分は `SMP-000123` が戻る） |
| **4列目** | **送り状番号＝伝票番号**（`391059321623`／ハイフンなし12桁） |

> 画面表示は `3910-5932-1623` とハイフン付きだが、CSV上はハイフンなしで格納される。

#### 6-4-1. 取り込みロジック

1. アップロードされたファイルを**Shift_JISとして読む**（ヘッダー行なし＝1行目から処理）
2. **1列目が `SMP-` で始まる行だけ**を抽出（通常注文の行は自動的に無視）
3. 4列目を伝票番号として取得し、**12桁の数字かを検証**
4. 1列目の申込IDで `sample_requests` を特定し、伝票番号を登録 → 発送済みに更新
5. 発送完了メールを送信

> **お客様管理番号の桁数**: B2の制限（半角20文字以内）に収まるよう `SMP-000123` 形式（10文字）とする。

#### 6-4-2. 伝票番号の表示形式

| 用途 | 形式 |
|---|---|
| 管理画面・メール本文 | `3910-5932-1623`（4桁区切りで読みやすく） |
| ヤマト追跡URL | `391059321623`（ハイフンなし） |
| DB保存 | ハイフンなしで保存し、表示時に整形 |


発送後、ヤマトで採番された**伝票番号**を申込に登録する。方法は2通り。

#### (A) 一括登録（B2クラウドの発送データを取り込む）★おすすめ

```
B2クラウドから当日の発送データをダウンロード
      ↓
管理画面「発送データを取り込む」からファイルをアップロード
      ↓
お客様管理番号が「SMP-」で始まる行だけを自動抽出
      ↓
申込IDと突き合わせ、伝票番号を一括登録 → 発送済みに更新
```

- **サンプル分だけの抽出はシステムが自動で行う**（当日の通常注文が混ざっていても問題なし）
- 取り込み結果を画面に表示する: 「○件登録しました／○件は該当なし（スキップ）」
- 同じファイルを2回取り込んでも二重登録しない（登録済みはスキップ）
- 該当しなかった行は一覧で表示し、原因が分かるようにする

#### (B) 個別登録

一覧の各行に伝票番号の入力欄を用意し、1件ずつ入力・保存できる。
（取り込みが失敗したときや、手書き送り状を使ったときの補助手段）

### 6-5. 発送完了メール

伝票番号が登録され発送済みになったら、アンバサダー本人へメールを送る。

- 宛先: `affiliates.email`
- 送信タイミング: **伝票番号の登録と同時**（一括・個別どちらも）
- 一括登録の画面には「**メールを送る**」チェックボックスを置く（初期値ON）。
  テスト時や再登録時にメールを送りたくない場合はOFFにできる
- 送信済みは `shipped_mail_sent_at` に記録し、**二重送信しない**

## 7. ヤマトB2クラウド CSV仕様（実装済み）

### 7-1. 取込みパターンは既存の「ネクストエンジン-通販用」をそのまま使う

パートさんが**通常注文と同じ操作**で取り込めるよう、新しいパターンは作らず、既存の紐付けに合わせてCSVを出力する。

> **経緯**: 当初は「基本レイアウト」の標準列順で出力したが、B2側の取込みパターンは
> 既にネクストエンジンのCSV用にカスタマイズされており、列が飛び飛びに対応していた。
> 各列に `C01`〜`C80` の目印を入れたダミーCSVを取り込ませることで、対応を確定させた。

### 7-2. 列の対応（実測で確定）

| CSV列 | B2の項目 | 出力する値 |
|---|---|---|
| 1 | お客様管理番号 | `SMP-000002`（申込ID） |
| 2 | 送り状種類【必須】 | **A**（ネコポス） |
| 5 | 出荷予定日【必須】 | 出力日（YYYY/MM/DD） |
| 9 | お届け先電話番号【必須】 | 申込の電話番号 |
| 11 | お届け先郵便番号【必須】 | 申込の郵便番号 |
| 12 | お届け先住所【必須】 | 都道府県＋市区町村＋番地 |
| 13 | お届け先建物名 | 建物名 |
| 16 | お届け先名【必須】 | 宛名 |
| 18 | 敬称 | （空欄・B2の既定に任せる） |
| 20 | ご依頼主電話番号 | 0274-20-1234 |
| 22 | ご依頼主郵便番号 | 375-0005 |
| 23 | ご依頼主住所 | 群馬県藤岡市中187-1 |
| 25 | ご依頼主名 | 大陸通商株式会社（うましっぽ） |
| 28 | 品名1 | ※**B2側の固定値が優先**（下記） |
| 3,6,7 | クール区分／お届け予定日／配達時間帯 | ネコポスは指定不可のため空欄 |

### 7-3. B2側の固定値（CSVでは変更できない項目）

| 項目 | 値 |
|---|---|
| 品名1 | **食品(馬肉など)** |
| ご請求先顧客コード | 0362623898 |
| ご請求先分類コード | 011 |
| 運賃管理番号 | 01 |

> 品名は「食品(馬肉など)」のまま運用する方針で確定（2026-09-12）。
> 中身はペットフードのため表記として問題なく、既存パターンを触らずに済むため。
> 変更する場合はB2側で品名1の固定値を外し、CSVの28列目に紐付ける（通常注文にも影響するため要検討）。

### 7-4. ファイル形式

| 項目 | 内容 |
|---|---|
| 文字コード | UTF-8（BOM付き） |
| 改行コード | CRLF |
| 引用符 | **全項目をダブルクォートで囲む**（先頭ゼロの消失を防ぐ） |
| 1行目 | 項目名（B2の「取込み開始行=2行目」に対応） |
| 列数 | 40列 |

### 7-5. ご依頼主（送り主）情報

| 項目 | 値 |
|---|---|
| 名称 | 大陸通商株式会社（うましっぽ） |
| 郵便番号 | 375-0005 |
| 住所 | 群馬県藤岡市中187-1 |
| 電話番号 | 0274-20-1234 |

## 11. Discord通知

サンプル申し込みがあったとき、**専用のWebhookへ通知**する。

- 既存の通知（登録・成果・支払い）とは**別のWebhook URL**を使う
- 設定: **管理画面の設定ページに入力欄を作る**（`settings` テーブルに `discord_sample_webhook_url` を追加）
  - チョクさん自身がいつでも貼り替えでき、URLを他者に渡す必要がない
  - 権限は「管理」ロール限定。画面では一部伏せ字で表示する
- 未設定の場合は通知をスキップする（エラーにしない）
- 通知内容: アンバサダー名／商品名／申込日時／送付先の都道府県
  - ※ 住所全体はDiscordに流さない（個人情報保護のため、詳細は管理画面で確認）

## 14. 注意点

- **本番DBにテーブルを2つ追加＋既存テーブルにカラム追加**するため、マイグレーション前にバックアップを取る
- 既存の `affiliates.sample_sent_at` は削除せず連動させる（既存画面を壊さない）
- マイページはスマートフォン利用が中心のため、追加UIもレスポンシブ対応
- 送付先住所は個人情報のため、Discord通知には都道府県までしか含めない
- CSVには氏名・住所・電話番号が含まれるため、ダウンロードしたファイルの取り扱いに注意（管理画面ログイン必須）
- **B2の発行済データCSVは実在顧客の個人情報を含む**。リポジトリ内に置かない（`.gitignore` で `*.csv` を除外済み）。取り込み後は速やかに削除する
- アップロードされたファイルはサーバーに保存せず、**読み取り後すぐ破棄**する（個人情報を残さない）
